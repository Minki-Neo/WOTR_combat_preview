# Combat Preview 0.3.1 — 읽기 전용 기본 무기 베타

턴제 전투에서 적을 가리키면 **기본 주무기 모델의 부분 추정**을 표시합니다.
DR/저항/보호막 사례를 기다리지 않고 현재 전투에서 UI와 기본 모델을 검증할 수 있도록 만든 베타입니다.
완전한 게임 예측기나 모든 무기/특기를 지원하는 제품은 아닙니다.

## 0.3.1 UI 변경

패널은 하단 행동/스킬 막대 위 중앙에 자동 배치합니다. 활성 게임 UI의 화면 경계를 읽으며
판독할 수 없으면 화면 높이의 74% 지점을 기준으로 배치합니다. 제목을 드래그하면 수동 위치로 전환하고,
UMM의 중앙 배치/위치 초기화로 복원합니다. 기존 0.3.0 설정도 첫 실행에 중앙 배치로 이관합니다.

직접 만든 짙은 배경·청동색 테두리·따뜻한 글자색을 사용합니다. 게임/다른 모드의 그림은 추출하거나
복제하지 않습니다. 이미 사용하는 GUI 폰트를 이어 쓰며, 생성한 텍스처는 이 모드가 정리합니다.
긴 계산 설명은 기본적으로 접고 ‘상세’에서 엽니다.

각 기본 공격 행에 다음 항목을 표시합니다.

| 항목 | 의미 |
|---|---|
| 명중률 | 현재 부분 모델의 기본 d20 확률 |
| 피해 주사위 | 구성별 줄바꿈: `1D8+4 +` 다음 줄 `1D6 (화염)` |
| 명중 시 평균 | 명중을 조건으로 치명타까지 가중한 평균. 기본적으로 방어 전 수치 |
| 방어 반영 기댓값 | 실제 DR/저항/보호막이 미확인이면 `—`. 아래에 방어 전 기댓값 표시 |
| 합계 기댓값 | 표시된 기본 반복 공격들의 합계. 실제 방어 반영 합계는 미확인이면 `—` |

기본 명중 시 평균은 RAW 기댓값 ÷ 명중 확률입니다. 일반 명중(치명 제외) 평균은 상세에서 따로 표시합니다.
명시적으로 확인한 수동 방어 시나리오는 별도 라벨로 반영할 수 있으나 실제 대상 방어가 아닙니다.

## 최근 게임 추정값 읽기

게임/다른 모드가 이미 만든 완료된 `IsFake` 공격 추정 이벤트가 관측되면 주무기의 AB/AC와 피해 구성을
숫자로 복사합니다. **이 모드가 가짜 공격을 생성하거나 실행하지 않습니다.** 실제 공격 통계에도 섞지 않습니다.
공격자/대상/무기/턴/모드/확인 가능한 상태가 일치하고 2초 이내일 때만 사용합니다.
추정값이 없거나 만료되면 기본 능력치 모델로 돌아가며 패널의 출처 표시가 달라집니다.
이 기능은 UMM에서 끌 수 있습니다. 이미 있는 게임 추정값을 읽는 것만으로 모든 특기/조건의 정확성이
보장되지는 않습니다. 실제 UI 경로에서 추정 이벤트가 생성되지 않으면 기본 모델만 표시됩니다.
추가 피해는 첫 구성만 기본 치명 배율을 적용하고 다른 구성은 비증폭으로 보는 부분 모델입니다.
기본 BAB 반복 공격 수는 그대로이며 가속/연타 등 추가 타격은 아직 합산하지 않습니다.

## 표시하는 값과 범위

- 대상의 현재/최대 체력과 양수인 임시 HP. 최대 0.2초 간격으로 갱신하며 판독 불가 시 확인 불가로 표시합니다.
- 저장된 BAB·기본 명중 능력치·추가 AB와 대상의 저장된 일반 AC.
- 주무기 단타 또는 BAB 기준 기본 반복 공격(최대 4행)의 -0/-5/-10/-15 모델.
- 기본 d20 명중/위협/확인 확률과 물리 기본 무기의 주사위·능력치·추가 피해 모델.
- 방어 적용 전 일반/치명타 피해 범위·평균·기대값. 합계도 **기본 모델 합계**입니다.
- 드래그 위치·너비·배율·상세 표시. 대상/유닛/공격 모드 변경 시 갱신하고 입력은 최대 0.2초 간격으로 다시 읽습니다.

가속/연타/보조손/자연/탈것 추가 공격, 강화/무기 특기/능력치 치환, 양손 그립 변경,
크기 변화, 강타 등 공격 시 보정, 협공/무방비/은폐/거울상/재굴림/치명타 면역/난이도 보정,
암습/발동/추가 원소 피해 등은 미반영입니다. 일반 자연 무기/비무장/이중 무기 자체는 베타에서 차단합니다.
실제 풀어택 전체 수·순서와 같다고 표시하지 않습니다. 기본 장비 데이터가 로드되지 않았으면 계산 불가를 표시합니다.

**DR·저항·면역·보호막 적용 후 피해는 계산 불가입니다.** 방어 파트가 없어도 0으로 확정하지 않습니다.
대상에 방어 관련 파트가 있으면 패널/로그에서 알리고, 실제 피해와 캐시 증거를 계속 기록합니다.
수동 시나리오는 기본 물리 모델에만 적용되며 실제 대상 판독이 아닙니다. 확인 체크는 세션마다 초기화됩니다.

## 실제 공격과 비교

화면에 실제 그려진 모델을 기억했다가 사용자가 실행한 실제 공격과 AB·AC·무기 주사위·보너스/구성 수를 대조합니다.
표시 후 2초 이내, 같은 공격자/대상/주무기/턴/모드이며 모델 입력 지문이 같을 때만 비교합니다.
이는 전체 게임 상태 동등성의 증거가 아닙니다. 차이는 **미반영 효과를 포함할 수 있는 모델 차이**이며 확정 버그 알람이 아닙니다.
조건 변경, 오래된 표시, 추가 타격, 무기/대상 교체는 비교 불가 사유를 기록합니다.

한 번의 실제 피해가 기대값과 다르다는 이유로 오류를 만들지 않습니다. 확률 검증도 단일 굴림으로 판정하지 않습니다.
`베타 모델 차이` 알림은 기본 OFF인 화면 안내입니다. 전투를 멈추거나 추가 공격/주사위를 실행하지 않습니다.

## 설치와 첫 시험

1. 게임을 완전히 종료하고 `CombatPreview-0.3.1-beta-UMM.zip`을 ModFinder의 로컬 ZIP 설치 또는 UMM으로 설치합니다.
2. 게임에서 Ctrl+F10 → **Combat Preview (Read-only Beta)** 설정을 엽니다.
3. **베타 무기 미리보기 켜기**를 체크합니다. 비교 로그는 기본 ON이며, 화면 알림은 원할 때 별도로 켭니다.
4. 일반 장검 등 제조 무기를 주무기로 든 캐릭터를 선택하고 턴제 전투에서 공격 가능한 적을 잠시 가리킵니다.
5. 패널을 확인한 뒤 실제 공격합니다. 화면 캡처와 `Mods/CombatPreview/CombatPreview.diagnostics.jsonl`로 검증합니다.
6. 문제가 생기면 미리보기 체크를 끄고 같은 폴더의 `CombatPreview.log`를 확인합니다. 제거는 게임 종료 후 ModFinder/UMM에서 합니다.

진단 체크박스를 별도로 켜지 않아도, 베타 미리보기+비교 기록을 켜면 로컬 로그가 생성됩니다.
기본 미리보기는 OFF입니다. 현재/이전 JSONL은 각각 1 MiB, 초당 최대 20행이며 자동 전송은 없습니다.
`docs/DIAGNOSTICS.ko.md`에서 각 로그의 의미를 확인하세요.

## 안전 경계와 현재 검증

기존 DryRun과 공격/피해 이벤트 재실행은 계속 차단합니다. 새 hover 경로는 Rulebook.Trigger,
새 공격/피해/주사위 생성, EnumerateFullAttack, live 감소/소모/정리를 호출하지 않습니다.
이미 저장된 능력치 필드와 장착 아이템 프록시, 이미 로드된 무기 종류 참조를 읽어 별도 순수 계산을 합니다.
게임의 실제 공격 before hook과 완료된 이벤트는 관측용으로만 사용합니다.
읽기 전용 필드 경로는 제공된 **2.7.0x MVID**에 한정하며 TTT는 현재 베타에서 차단합니다.

0.3.0 사용자 스크린샷에서 패널/대상 체력 표시를 확인했고 로그에서 표시 29건·비교 연결 10건을 확인했습니다. 비교 가능한 4건은 모두 AB 차이가 있어 정확도가 확인된 것은 아닙니다. **0.3.1의 새 UI·게임 추정 사본 경로는 아직 사용자 게임에서 실행 검증하지 않았습니다.**
전체 상태/모든 RNG 비간섭의 계측 검증 역시 남아 있습니다. 상세 근거는 `docs/VALIDATION.md`와 `docs/SAFETY_AUDIT.md`를 참고하세요.

## 개발

프로젝트 루트 `CombatPreview/`에서 .NET 8 SDK와 Python 3으로 실행합니다.

```bash
dotnet run --project tests/CombatPreview.Tests.csproj -c Release
python3 tests/reference_check.py
python3 -m venv .venv
.venv/bin/python -m pip install tree-sitter==0.25.2 tree-sitter-c-sharp==0.23.1
.venv/bin/python tests/syntax_check.py
```

Windows Python 가상환경 경로는 `.venv/Scripts/python.exe`입니다.
순수 베타 로그 예시(실제 게임 검증 아님):

```bash
dotnet run --project tests/CombatPreview.Tests.csproj -c Release -- --beta-fixture /tmp/combat-preview-beta-example.jsonl
```

본인 게임의 Managed/UMM DLL은 저장소 밖에 둡니다.

```bash
python3 tools/package.py --managed-dir "게임의 Managed 폴더" --umm-dir "UMM DLL 폴더"
```

또는 `dotnet build CombatPreview.csproj -c Release -p:GameDir="게임 설치 경로" -p:UmmDir="UMM DLL 폴더"`.
패키지는 빌드 성공 후 모드 DLL·설정·라이선스·안내서만 포함하며 게임 참조 DLL은 포함하지 않습니다.
