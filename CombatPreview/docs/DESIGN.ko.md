# 기술 설계 및 조사 결론 — 0.2.0 설계 이력

> 0.2.1 현재 동작: 아래 DryRun 기반 경로는 항상 차단됩니다. 현재 설계·검증 경계는
> README.ko.md, SAFETY_AUDIT.md, DEFENSE_ADAPTERS.ko.md를 확인하세요.

Success Chance는 이미 WotR 풀어택 열거와 타격별 예측을 구현하고 있습니다.
원본 HoverChance.Series는 UnitAttack.EnumerateFullAttack을 사용하며,
AttackPrediction은 Hit/Crit/AB/AC 및 일반·치명타 피해 범위를 제공합니다.
따라서 타격별 계산을 처음부터 재작성하지 않고, 독립된 UMM ID와 네임스페이스의 MIT 파생 모드로 구성했습니다.

Hit Chance Overlay의 소스 라이선스도 MIT이지만 코드는 재사용하지 않았습니다.
Nexus 페이지의 파일/에셋 권한과 GitHub 소스 라이선스는 구분했습니다.

## 데이터 흐름

1. hover/highlight 대상과 턴제 현재 유닛·행동 상태를 읽습니다.
2. 게임이 열거한 공격 손/무기/페널티를 가져옵니다.
3. 공격 컨텍스트에 IsFullAttack/IsFirstAttack/AttackNumber를 전달합니다.
4. 원본 DryRun 기반 공격 예측기로 AB·AC·은폐·치명타 확률을 계산합니다.
5. 무기 스탯 DamageDescription의 주사위·보너스를 읽고 원본의 pending damage를 반영합니다.
6. 순수 DamageMath에서 분포를 합성해 최소·평균·최대를 계산합니다. 계산 예산 초과는 실패 처리합니다.
7. 무조건부 명중/치명 확률로 기대 피해를 계산하고, 고정 상태 가정의 합계를 IMGUI 패널에 그립니다.

## 보장과 보장하지 못하는 부분

DamageMath와 D20은 RNG를 사용하지 않는 계산 코드입니다.
그러나 게임 연동 DryRun은 사전 이벤트 핸들러를 호출하므로 완전한 읽기 전용 샌드박스가 아닙니다.
일부 핸들러를 Harmony로 억제하고 원본 정리 코드를 사용하며, 추가로 Unity RNG와 규칙 컨텍스트를
finally에서 복원합니다. 임의 모드 핸들러가 다른 상태를 변경하는 경우까지 복구할 수는 없습니다.

생산용 출시에는 게임 버전 고정, 모든 호출 경로의 상태 변경 감사, 게임 RNG 식별,
런타임 상태 해시 및 다음 주사위열 동등성 검증이 필요합니다. 안전성 검증 전에는 opt-in 실험 상태를 유지합니다.

DR/저항은 단순히 평균에서 빼면 부정확합니다. 실제 피해 유형·바이패스·면역·분포별 하한을
검증할 수 있는 읽기 전용 어댑터를 추가한 후 구현해야 합니다. 현재 화면은 raw를 명시합니다.

## 0.2.0 구현 경계

`DamageTerm.Kind`로 피해 종류를 보존합니다. `MitigationMath`는 독립 DTO의 완전성,
피해 종류, 소모형 보호막 여부를 검사한 뒤 정적 유형별 분포를 계산합니다.
완전하지 않은 스냅샷은 0 피해나 0 저항으로 대체하지 않습니다.
`DefenseReader.Read`는 실제 게임 방어 어댑터가 미검증이므로 항상 불가 상태를 반환합니다.
수동 `Scenario`는 사용자가 확인한 모델 입력이고 자동 판독과 별도입니다.
소모형 풀은 입력 모델에 표시할 수 있으나 계산은 명시적으로 거부합니다.

`Compatibility`는 게임 버전과 어셈블리 정보를 읽고 알려진 주요 API의 존재를 검사합니다.
이 검사는 모든 시그니처/의미론의 검증을 대체하지 않으며 통과해도 UNVERIFIED입니다.
TTT 감지는 로드된 어셈블리 수준이며 해당 설정 활성화 여부나 유닛 방어 구현을 확정하지 않습니다.
실제 TTT 어댑터를 선택하거나 지원 완료로 표시하지 않습니다.
