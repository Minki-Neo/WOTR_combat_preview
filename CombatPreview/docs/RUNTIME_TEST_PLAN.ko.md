# 0.3.1 UI 첫 시험 — 아직 실행하지 않음

0.3.0에서는 패널 표시와 일부 비교 연결을 확인했습니다. 아래는 새 UI/추정 사본의 검증입니다.

1. 게임 종료 후 0.3.1 ZIP 설치. 기존 설정도 첫 실행에 중앙 배치/간략 표시로 이동해야 합니다.
2. 일반 주무기로 적을 가리켜 행동/스킬 막대 바로 위 중앙에 뜨고 막대를 가리지 않는지 확인합니다.
3. 명중률 / 주사위 / 명중 시 평균 / 방어 반영 기댓값 열과 풀어택 기본 행별 값·합계를 캡처합니다.
4. 추가 피해가 있는 게임 추정이 관측되면 피해 구성별 줄바꿈을 확인합니다. 관측 추정이 없으면 기본 모델만
   표시되며 임의의 추가 주사위를 만들어서는 안 됩니다. 상세에서 AB/AC/일반 명중 평균을 확인합니다.
5. 대상/무기/턴/버프/공격 모드 변경, 추정 만료 후 출처가 적절히 갱신되는지 확인합니다.
   source가 observed-existing-estimate인 beta-preview와 대응하는 실제 공격의 비교를 확인합니다.
6. 수동 방어를 선택하지 않은 상태에서 DR 반영 수치는 미확인 `—`, 방어 전 값은 별도로 보여야 합니다.
   수동 DR를 입력/확인했다면 수동 라벨/로그가 붙고 실제 대상 방어로 기록되지 않아야 합니다.
7. 해상도/배율 변경, 제목 드래그, UMM 위치 초기화, UMM 비활성화/재활성화, 장면 전환을 확인합니다.
8. 패널 캡처와 diagnostics.jsonl을 전달합니다. 가속/연타 등 모델 밖 추가 공격을 전체 공격 합계로
   잘못 해석하지 않습니다. 전체 상태/모든 RNG 시험도 아래 이력 계획에서 이어갑니다.

# 실제 게임 검증 계획 — 0.3.0 베타

## 지금 가능한 첫 시험 — 아직 실행하지 않음

DR·저항·보호막 적을 기다릴 필요 없이 현재 저장의 일반 적으로 시작합니다.

1. 0.3.0 베타 ZIP 설치 후 게임을 시작하고 Ctrl+F10에서 미리보기와 비교 기록을 켭니다.
2. 일반 제조 무기를 주무기에 장착하고 턴제 전투의 자기 턴에 공격 가능한 적을 1초 가리킵니다.
3. 대상 이름, 현재/최대 HP, 임시 HP(있는 경우), 기본 AB/AC·확률·RAW 기대값을 캡처합니다.
4. 실제 단타를 실행하고 전투 로그의 AB/AC/무기 주사위와 대조합니다.
   beta-preview → observation.betaPreviewId → beta-comparison → damage-observation 연결을 확인합니다.
5. 가능하면 이동 없이 기본 반복 공격도 시험합니다. 가속 등 추가 공격은 미지원 표시/skip 대상입니다.
6. 피해·치유·최대 HP 버프·임시 HP 변화 뒤 다시 가리켜 체력이 갱신되는지 확인합니다.
   대상 변경/사망/불러오기/장면 전환/UMM toggle 때 이전 대상의 체력이 남지 않아야 합니다.
   최대 체력이나 읽기 필드가 없으면 확인 불가로 표시하며 0으로 확정하지 않습니다.
7. 상세/간략, 해상도/배율, 패널 드래그와 설정 저장, 미지원 무기·선택 능력·사거리 밖 숨김을 확인합니다.
8. 화면 알림을 켜고 실제 AB가 기본 모델과 다른 공격에서 알림과 differentFields를 확인합니다.
   미반영 효과는 확정 버그가 아닙니다. 무작위 피해가 기대값과 다르다는 이유로 경고하면 실패입니다.
9. 패널 캡처와 모드 폴더의 diagnostics.jsonl 및 오류가 있으면 CombatPreview.log를 전달합니다.

추후 DR/저항/보호막 적이 나오면 실제 피해/방어 증거를 수집합니다. 이번 버전은 방어 후 피해를
예측하지 않으므로 방어 계산 정확도 통과로 처리하지 않습니다. 기존 이벤트 재실행은 계속 차단합니다.
전체 상태/모든 RNG 비간섭 검증도 아래 계획에 따라 별도로 필요합니다.

## 아래는 이전 목표/진단 빌드의 이력

0.2.x에서 차단한 hover와 달리 0.3.0은 별도의 읽기 전용 기본 무기 모델만 opt-in으로 표시합니다.
아래 고급 공격/방어 항목은 이번 베타의 지원 기능이나 통과 기록이 아닙니다.

기본 모드 구성으로 시작하고, 각 케이스에서 게임 버전·UMM 버전·능력치·버프·무기·대상·스크린샷·전투 로그를 기록합니다.

| 케이스 | 확인 사항 |
|---|---|
| 뮤테이션 워리어, 롱소드, BAB 16 | 4타 기본 순서, 반복 페널티 0/5/10/15, 로그 AB와 비교 |
| 같은 캐릭터 + 가속 | 추가 최고 AB 공격의 수·순서, 가속 만료 후 0.35초 내 갱신 |
| 강타 ON/OFF | 첫 공격 전에 적용되는 페널티·추가 피해와 실제 로그 비교 |
| 롱소드 기마 오라클 | 기수 선택, 탈것 선택, 이동 전후 풀어택 여부; 탈것 피해 제외 표시 |
| 협공·버프·디버프 | 대상/위치/상태 변경 뒤 AB·AC 재계산 |
| 은폐 20%/50%, 거울상 | 첫 공격 확률; 거울상 후속 타격 수치는 고정 상태 근사임을 확인 |
| 치명타 19–20/x2, 향상된 치명타 | 위협 범위·확인 보정·면역·강화된 치명타 배율 로그 비교 |
| Flaming 등 추가 원소 피해 | 일반 주사위·치명타시 배율 제외·정적 보너스 표시 |
| DR·저항·면역 | 항상 raw 표시, 실제 피해로 잘못 표기하지 않는지 확인 |
| 이동/행동 소모/사거리 밖 | 단타/풀어택 전환, 공격 불가능 시 숨김 |
| 주문·돌진·기회공격 | 미지원 동작을 일반 풀어택으로 표시하지 않는지 확인 |
| 소환/장면 변경/불러오기/대상 사망 | 오래된 대상 패널이 남지 않는지 확인 |
| 해상도·UI 배율 변경 | 패널 화면 내 유지·드래그·설정 저장 |
| UMM 비활성화/재활성화 | 예측 중단·복귀, 원본 공격 결과 변경 없음 |

## 상태 및 RNG 비간섭 — 출시 차단 조건

동일 저장 파일·동일 입력에서 미리보기 OFF와 ON을 비교합니다. 단순 HP 비교로 충분하지 않습니다.

- 예측 전후 HP, 임시 HP, 버프/지속시간/랭크, 자원, 토글, 행동 상태, 공격 횟수,
  fact runtime 상태, 규칙 컨텍스트, Unity RNG와 게임이 실제 사용하는 모든 RNG를 계측합니다.
- 적에 1,000회 hover/해제, 대상 교체, 턴 전환을 해도 상태 해시가 같아야 합니다.
- 다음 실제 공격·피해 주사위열이 동일해야 합니다. 전투 로그의 숨은 이벤트도 비교합니다.
- 예측 본문/정리 핸들러에 테스트 예외를 발생시켜 중첩 깊이·컨텍스트·임시 보정 복원을 검사합니다.
- 원본 게임 구성이 통과한 다음 사용하는 다른 모드를 하나씩 켭니다.
- 하나라도 차이가 있으면 기본 OFF를 유지하고 일반 배포를 중단합니다.

현재 Unity Random.state 복원은 다른 RNG나 상태를 포괄하지 않습니다.
패널 표시만 성공한 것은 이 검증을 통과했다는 뜻이 아닙니다.

## 0.2.0 추가 검증 — 아직 실행하지 않음

- 자동 방어 정보가 없으면 실제 대상 적용 후 피해가 항상 UNAVAILABLE인지 확인.
- 수동 시나리오 결과에 MANUAL SCENARIO가 계속 표시되는지 확인.
- 물리 1d8+15 + 화염 1d6, DR10/화염저항5, Hit .75/Crit .075에서 모델 기대값 8.7125.
- DR 관통 시나리오를 켜면 물리 DR만 무시하고 원소 저항은 유지되는지 확인.
- 물리/화염 면역 설정이 해당 유형에만 적용되는지 확인.
- 세션 재시작 시 수동 시나리오 확인 체크가 초기화되는지 확인.
- 필수 API 누락을 주입하면 어떤 Harmony 패치도 적용하지 않고 진단 화면만 표시하는지 확인.
- 패치 설치 중 예외 주입 시 이 모드 소유 패치가 모두 롤백되는지 확인.
- 실제 게임 버전/MVID/UMM/Harmony/TTT 로그가 로드된 어셈블리와 일치하는지 확인.

## 0.2.1 현재 빌드에 대한 인수 순서 — 모두 미실행

위 0.2.0 계획은 목표 동작의 이력이며 통과 기록이 아닙니다. 0.2.1에서는 hover를 항상 차단하며
DryRun 복원/패치를 실행하지 않습니다. 먼저 진단용 패키지의 UMM 로드, 기본 OFF, 이벤트 구독,
실제 단타/풀어택의 관측 ID 연결, 피해 이벤트, 파일 회전, ModFinder 설치/제거를 확인합니다.
TTT 미사용 환경으로 시작합니다. 게임 리소스의 정확한 표시 버전, 실행 시 로드된 Harmony 버전과
MVID를 기록합니다. 제공된 UMM 참조 Harmony 2.3.6과 게임 Managed의 Harmony 2.0.4가 서로 다르므로
실제 로딩 구성을 로그로 확인해야 합니다. 파일을 임의 버전으로 교체하지 않습니다.

진단 OFF/ON의 동일 저장 파일·동일 입력에서 HP/자원/버프/행동/보호막/context/모든 RNG 및 다음 실제
굴림을 비교합니다. 로드/장면 전환/중첩 이벤트/관측 예외/UMM toggle/부분 등록 실패를 검사합니다.
게임 로그의 damage.Result는 HP 감소량과 별개이므로 임시 HP/리다이렉트 사례도 별도로 기록합니다.

차단된 미리보기가 보이지 않는 것을 정확도 테스트 통과로 기록하지 않습니다. P0 상태 비간섭의
런타임 검증, P1 자동 방어 적용/정확도 UI/실시간 예측 비교 및 P2 연속 보호막은 아직 완료가 아닙니다.

## 0.2.2에 이어갈 사항

사용자가 제공한 0.2.1 로그에서는 로드와 일부 단타/풀어택/치명타/피해 이벤트 연결이 관측됐습니다.
통제된 수치 비교·비간섭·예외·장면 전환 시험을 통과한 것은 아닙니다. RUNTIME_LOG_REVIEW.ko.md의
집계와 구분하세요. 0.2.2는 새 schema/세션/버전/UsePool 판독/가짜 이벤트 제외 동작을 실제 게임에서 재확인해야 합니다.
