> 현재 진단용 빌드에서는 hover/DryRun을 활성화할 수 없습니다.

## 상태 및 RNG 비간섭 — 출시 차단 조건

동일 저장 파일·동일 입력에서 미리보기 OFF와 ON을 비교합니다. 단순 HP 비교로 충분하지 않습니다.

- 예측 전후 HP, 임시 HP, 버프/지속시간/랭크, 자원, 토글, 행동 상태, 공격 횟수,
  fact runtime 상태, 규칙 컨텍스트, Unity RNG와 게임이 실제 사용하는 모든 RNG를 계측합니다.
- 적에 1,000회 hover/해제, 대상 교체, 턴 전환을 해도 상태 해시가 같아야 합니다.
- 다음 실제 공격·피해 주사위열이 동일해야 합니다. 전투 로그의 숨은 이벤트도 비교합니다.
- 예측 본문/정리 핸들러에 테스트 예외를 발생시켜 중첩 깊이·컨텍스트·임시 보정 복원을 검사합니다.
- 원본 게임 구성이 통과한 다음 사용하는 다른 모드를 하나씩 켭니다.
- 하나라도 차이가 있으면 기본 OFF를 유지하고 일반 배포를 중단합니다.

현재 Unity Random.state 복원은 다른 RNG나 상태를 포괄하지 않습니다.
패널 표시만 성공한 것은 이 검증을 통과했다는 뜻이 아닙니다.

## 0.2.0 추가 검증 — 아직 실행하지 않음

- 자동 방어 정보가 없으면 실제 대상 적용 후 피해가 항상 UNAVAILABLE인지 확인.
- 수동 시나리오 결과에 MANUAL SCENARIO가 계속 표시되는지 확인.
- 물리 1d8+15 + 화염 1d6, DR10/화염저항5, Hit .75/Crit .075에서 모델 기대값 8.7125.
- DR 관통 시나리오를 켜면 물리 DR만 무시하고 원소 저항은 유지되는지 확인.
- 물리/화염 면역 설정이 해당 유형에만 적용되는지 확인.
- 세션 재시작 시 수동 시나리오 확인 체크가 초기화되는지 확인.
- 필수 API 누락을 주입하면 어떤 Harmony 패치도 적용하지 않고 진단 화면만 표시하는지 확인.
- 패치 설치 중 예외 주입 시 이 모드 소유 패치가 모두 롤백되는지 확인.
- 실제 게임 버전/MVID/UMM/Harmony/TTT 로그가 로드된 어셈블리와 일치하는지 확인.

## 0.2.1 현재 빌드에 대한 인수 순서 — 모두 미실행

위 0.2.0 계획은 목표 동작의 이력이며 통과 기록이 아닙니다. 0.2.1에서는 hover를 항상 차단하며
DryRun 복원/패치를 실행하지 않습니다. 먼저 진단용 패키지의 UMM 로드, 기본 OFF, 이벤트 구독,
실제 단타/풀어택의 관측 ID 연결, 피해 이벤트, 파일 회전, ModFinder 설치/제거를 확인합니다.
TTT 미사용 환경으로 시작합니다. 게임 리소스의 정확한 표시 버전, 실행 시 로드된 Harmony 버전과
MVID를 기록합니다. 제공된 UMM 참조 Harmony 2.3.6과 게임 Managed의 Harmony 2.0.4가 서로 다르므로
실제 로딩 구성을 로그로 확인해야 합니다. 파일을 임의 버전으로 교체하지 않습니다.

진단 OFF/ON의 동일 저장 파일·동일 입력에서 HP/자원/버프/행동/보호막/context/모든 RNG 및 다음 실제
굴림을 비교합니다. 로드/장면 전환/중첩 이벤트/관측 예외/UMM toggle/부분 등록 실패를 검사합니다.
게임 로그의 damage.Result는 HP 감소량과 별개이므로 임시 HP/리다이렉트 사례도 별도로 기록합니다.

차단된 미리보기가 보이지 않는 것을 정확도 테스트 통과로 기록하지 않습니다. P0 상태 비간섭의
런타임 검증, P1 자동 방어 적용/정확도 UI/실시간 예측 비교 및 P2 연속 보호막은 아직 완료가 아닙니다.
