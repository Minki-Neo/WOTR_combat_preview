## 진단에서 드러난 문제와 수정

1. 부모 무기 공격 없이 이름 없는 대상을 상대로 AC10인 굴림 15건이 섞였습니다. 기존 로그에는 IsFake가
   없어 이들이 모두 가짜라고 판정할 수 없습니다. 0.2.2는 게임의 IsFake 플래그가 true인 이벤트를
   제외하고, 그 외 부모 없는 굴림은 unassociated-observation으로 분리합니다. 예측 비교에는 사용하지 않습니다.
2. defenseEvidence의 512자 제한 때문에 긴 미지원 안내 뒤의 캐시 상세 7건이 가려졌습니다.
   0.2.2는 defenseMissing/defenseObserved 배열로 분리하고 개별 항목의 길이와 배열 크기를 제한합니다.
3. 양수 m_RemainPool로 HasConsumablePool을 설정하던 코드는 잘못됐습니다. 제공된 게임 DLL의
   AddDamageResistanceBase.ComponentRuntime은 UsePool=false일 때도 이 캐시를 초기화할 수 있습니다.
   0.2.2는 blueprint backing field의 실제 UsePool을 읽습니다. 값 미상은 Unknown, true/잔량0도 Present입니다.
   기존 7건 모두 실제로 보호막이 없었다고 단정할 수는 없습니다. 새 로그에서 UsePool 값을 확인해야 합니다.
4. 0.2.1 로그에는 세션 구분과 게임 버전이 없었습니다. 0.2.2 schema 2는 모든 행에 sessionId,
   recordSequence, runtime 버전/MVID를 넣어 재시작/파일 회전 후에도 출처를 구분합니다.

모든 NoPrediction은 기존 미리보기 차단 정책에서 예상한 결과입니다. rawDamage와 reportedDamage의
차이를 DR 또는 예측 오차로 판정하지 않습니다. 이 필드들은 실제 피해 계산의 서로 다른 단계이며,
수정자/난이도/최소값/리다이렉트/임시 HP의 의미가 다릅니다.
