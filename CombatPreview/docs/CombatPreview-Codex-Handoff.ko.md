## 3. 최종 제품 목표와 범위

《Pathfinder: Wrath of the Righteous》 턴제 전투에서 공격 가능한 적을 가리킬 때 한 패널에 다음 정보를 제공한다.

- 공격 순서별 명중 보너스, 대상 AC, 명중 확률.
- 풀어택 반복 페널티와 가속·양손/보조손·추가 공격의 게임 내 순서.
- 공격별 피해 주사위, 최소·평균·최대 피해.
- 치명타 위협·확인·배율을 반영한 공격별 기대 피해.
- DR·원소 저항·면역·관통 조건을 반영한 기대 피해와 풀어택 합계.
- 패널 위치/너비/배율 조절 및 상세/간략 표시.
- 정확도, 계산 누락, 지원하지 않는 효과를 숫자와 함께 표시.

핵심 검증 캐릭터: 롱소드 기마 오라클, 뮤테이션 워리어, 가속 풀어택.
기수와 탈것 공격을 혼동하지 않는다. 탈것 합산은 별도 명시 없이 지원했다고 표시하지 않는다.
돌진·기회공격·광선 주문은 후속 범위다. 우선 일반 무기 단타/풀어택을 안정화한다.

### 필수 제약

- 미리보기 때문에 HP, 버프, 자원, 행동 상태, 보호막 잔량, 전투 기록 또는 난수열이 바뀌면 안 된다.
- 실제 피해 적용 함수를 미리보기 용도로 호출하지 않는다.
- 알 수 없는 방어 효과를 저항 0 또는 피해 0으로 대체하지 않는다.
- 수동 시나리오를 실제 적의 자동 계산 결과처럼 표시하지 않는다.
- 실제 게임에서 확인하지 않은 버전을 지원 완료로 표시하지 않는다.

### 기존 검증 이력

- WOTR 전처리 분기 선택 후 C# 18개 파일의 tree-sitter 구문 검사 통과.
- 독립 Python 수학/설정 검사 509개 통과.
- 프로젝트 XML 2개 파싱 및 ZIP 무결성 검사 통과.
- C# 테스트에는 6,699개 예정 assertion이 있으나 **실행하지 못했다**. 새 환경에서 실제 실행 결과를 확인한다.
- .NET SDK 8.0.408 실행은 이전 환경에서 `Failed to create CoreCLR, HRESULT: 0x8007000E`로 실패.
- 로컬 Mono 실행은 `Mono requires /proc to be mounted.`로 실패.
- 게임 DLL/실행 파일이 없어서 게임 API 컴파일과 런타임 검증도 하지 못했다.

위 실패는 이전 작업 환경의 결과다. 대상 Codex 환경에서도 실패한다고 가정하지 말고 다시 확인한다.

## 6. 다음 작업: 우선순위와 완료 조건

### P0-A. 재현 가능한 빌드와 실제 C# 테스트

1. 대상 저장소의 AGENTS.md 등 작업 지침을 먼저 확인한다.
2. SDK/OS/소스 버전과 입력 ZIP 해시를 기록한다.
3. 순수 계산 C# 테스트를 실제 컴파일·실행한다.
4. 게임 DLL이 있으면 전체 빌드의 참조·접근 제한·API 변경 오류를 해결한다.
5. 게임 DLL이 없으면 게임용 스텁으로 성공한 결과를 실제 모드 빌드 성공으로 보고하지 않는다.

완료 조건: 테스트 명령/종료 코드/통과 수를 기록하고, 전체 빌드 여부를 별도로 표시한다.

### P0-B. 미리보기 상태 변경 경로 감사

`DryRun.Run`, `Rulebook.Trigger`, `OnEventAboutToTrigger`, 임시 수정자, 컨텍스트 push/pop,
Unity/게임/모드 RNG 접근 및 예외 정리 경로를 추적한다.

- 미리보기에서 호출하는 각 게임 API/핸들러의 입력·반환·변경 가능 상태·복구 방식을 목록화한다.
- 알려진 일부 핸들러를 막았다는 이유로 모든 모드에 안전하다고 가정하지 않는다.
- 얕은 복사 객체가 실제 fact/buff/runtime 객체를 계속 참조하지 않는지 확인한다.

- 예측 OFF 또는 API 검사 실패 시 예측용 이벤트가 실행되지 않게 한다.

완료 조건: `docs/SAFETY_AUDIT.md`에 확인/미확인 경로와 차단 정책 기록.
실제 상태 및 난수 보존 완료 판정은 게임 계측 테스트 이후에만 가능하다.

### P1-A. 자동 방어 판독 어댑터

기본 게임용과 TTT용 어댑터를 분리하고 순수 계산 DTO로 변환한다.
다음 이름은 제안이며 기존 코드에 맞게 조정할 수 있다.

- `DefenseSnapshot`: 출처, 게임/규칙 구현, 완전성, 누락 이유, 적용 범위.
- `DamageComponentSnapshot`: 피해 유형, 주사위/보너스, 치명타 적용 여부, 관통 관련 속성.
- `IDefenseSnapshotProvider`: 읽기 전용 판독 계약.
- `PredictionQuality`: 지원 범위 내 계산 / 부분 추정 / 계산 불가.

판독 대상:

- 물리 DR 및 재질·강화·성향·피해 형태·복합 AND/OR 관통 조건.
- 복수 DR의 선택/명시적 중첩, 관련 특기의 감소량 보정.
- 원소별 저항·면역·면역/저항 억제 상태.
- 소모형 보호 효과 존재와 잔량. 초기에는 안전하게 미지원 처리해도 된다.
- 기본 게임과 TTT의 실제 적용 여부. 어셈블리 존재만으로 TTT 규칙 활성화를 확정하지 않는다.
- 아직 처리하지 못하는 취약성·난이도 배율·추가 피해 수정자를 명시한다.

금지: live `ApplyDamageReduction`, `SpendPool`, `Cleanup` 호출로 결과를 얻는 방식.
실제 게임 객체에 대한 임시 변경 후 복원을 자동으로 안전하다고 간주하지 않는다.

완료 조건: 지원하는 최소 사례에서 실제 대상의 방어값으로 자동 계산되며, 미지원 효과가 있으면
명시된 정책에 따라 부분 추정 또는 계산 불가로 표시된다. 불완전한 판독을 `Complete=true`로 설정하지 않는다.
게임 DLL이 없으면 계약·fixture 테스트·판독 코드 초안까지 구현하고 연동 검증을 남겨 둔다.

### P1-B. 정확도와 누락 표시

- 타격마다 결과 상태와 구체적 누락 이유를 표시한다.
- raw, 실제 대상 방어 반영, 수동 시나리오를 눈에 띄게 구분한다.
- 예: “일부 효과 누락: 암습”, “계산 불가: 소모형 보호막”, “TTT 방어 어댑터 미지원”.
- 전체 합계는 모든 타격의 상태를 반영한다. 일부 타격만 합산한 값을 전체 풀어택 피해로 표시하지 않는다.
- 버프/장비/턴/대상 변경, 장면 전환 시 이전 계산이 남지 않게 한다.
- 수동 시나리오 확인은 세션마다 필요하다는 기존 동작을 유지한다.

완료 조건: 숫자만 보고 실제 적용 피해로 오인할 수 없고, 상세 패널에서 근거·누락 항목을 확인할 수 있다.

### P1-C. 실전 비교용 진단 모드

기본 OFF인 로컬 진단 모드를 추가한다. 자동 전송은 하지 않는다.

- 예측 당시의 공격자/대상/무기/턴/타격 식별 정보와 조건을 기록한다.
- AB, AC, 페널티, 피해 구성, 방어 출처, 확률·예상 범위를 기록한다.
- 실제 공격 이벤트의 관측 결과와 연결한다. 진단을 위해 별도의 공격/주사위를 실행하지 않는다.
- 예측과 실제 공격 사이에 상태가 바뀌면 비교 불가로 표시한다.
- 한 번의 무작위 피해가 기대값과 다르다는 이유로 불일치로 판정하지 않는다.
- AB/AC/피해 구성/감소 규칙처럼 비교 가능한 결정적 값과 확률 검증을 분리한다.
- 로그 빈도/용량을 제한하고 재진입·중복 기록을 방지한다.

완료 조건: 동일 조건에서 예측·실제 값을 추적 가능한 로컬 보고서와 재현 절차를 제공한다.

### P2. 소모형 보호막의 연속 계산

P0/P1 이후 진행한다. 타격별 명중/빗나감/치명타/피해 분기에 따라 복사한 보호막 잔량을 갱신한다.
평균 피해만 잔량에서 빼는 방식은 정확한 확률 계산이 아니다.
상태 수 제한, 시간 예산, 근사 사용 여부를 명시한다. 실제 게임의 보호막은 절대 소모하지 않는다.

## 7. 수학 계약과 주의점

`Hit`는 치명타를 포함한 무조건부 명중 확률, `Crit`는 무조건부 확정 치명타 확률이다.

`E = (Hit - Crit) × 일반 명중 평균 + Crit × 치명타 평균`

- DR/저항은 각 주사위 결과에 적용한 후 평균을 구한다.
- 무기 피해와 치명타 배율이 적용되지 않는 추가 피해를 구분한다.
- 0.2.0의 “같은 피해 종류를 합쳐 한 번 감소”는 수동 정적 모델이다. 이를 모든 게임 효과에 일반화하지 않는다.
- 서로 다른 관통 조건의 물리 피해 항목, 유형별 적용 단위와 최소 피해 규칙은 게임 구현으로 확인한다.
- 거울상 소모/대상 사망/첫 명중 이후 버프 소모를 계산하지 않는 동안은 고정 상태 가정을 표시한다.
- 원본 d20 수정자 처리는 최대 8개 제한이 있다. 초과 시 조용히 정확한 값으로 표시하지 않도록 검토한다.

수동 모델 회귀 예:

- 물리 `1d8+15`, DR10, 화염 `1d6`, 화염저항5.
- 일반 평균 = `9.5 + 1/6 = 9.6666666667`.
- x2 치명 평균 = `29 + 1/6 = 29.1666666667`.
- Hit=.75, Crit=.075이면 기대 피해 = `8.7125`.

이 수치는 모델 테스트이며 실제 게임 관측 결과가 아니다.

## 8. 빌드 및 테스트 명령

현재 프로젝트는 모드 `net472`, 순수 테스트 `net8.0`, WOTR 전처리 상수를 사용한다.
실제 게임/UMM과 맞지 않으면 근거를 기록하고 수정한다.

프로젝트 루트 `CombatPreview/`에서:

```powershell
dotnet run --project tests/CombatPreview.Tests.csproj -c Release
./build.ps1 -GameDir 'C:\Program Files (x86)\Steam\steamapps\common\Pathfinder Second Adventure'
```

UMM 경로가 다르면:

```powershell
./build.ps1 -GameDir 'D:\Games\Pathfinder Second Adventure' -UmmDir 'D:\Path\To\UMM'
```

직접 빌드:

```powershell
dotnet build CombatPreview.csproj -c Release -p:GameDir='D:\Games\Pathfinder Second Adventure'
```

추가 검사:

```bash
python tests/reference_check.py
python -m pip install tree-sitter tree-sitter-c-sharp
python tests/syntax_check.py
```

현재 패키징 스크립트는 Info.json의 버전으로 `dist/CombatPreview-<version>-experimental-UMM.zip`을 만든다.
최종 ZIP은 모드 DLL·Info.json·라이선스·안내서만 포함하고 게임 참조 DLL은 포함하지 않아야 한다.
빌드가 성공하기 전에는 설치용 ZIP을 만들거나 설치 가능하다고 표시하지 않는다.

## 11. 결과물과 보고 형식

- 변경된 C# 소스와 실행 가능한 계산 테스트.
- 자동 판독의 지원/미지원 범위 및 정확도 표시 정책.
- 상태 변경 경로 감사 문서와 진단 모드 사용 안내.
- 실제 빌드 성공 시 모드 DLL 및 UMM 설치 ZIP.
- 한국어 설치/설정/제거 안내와 알려진 제한.
- 게임/UMM/모드 버전, 명령, 실제 결과가 포함된 검증 기록.

최종 보고는 다음을 구분한다.

1. 구현 완료: 어떤 동작이 바뀌었는지.
2. 검증 완료: 실제 실행한 명령/테스트와 결과.
3. 미검증: 컴파일 또는 게임 실행이 필요한 항목.
4. 남은 제한: 계산에서 제외된 효과와 표시 방식.
5. 다음 입력: 사용자가 제공해야만 진행할 수 있는 최소 파일/환경.

단계별 완료와 전체 제품 완료를 혼동하지 않는다. 자동 판독 미구현 상태를 수동 계산 UI로
대체한 뒤 자동 방어 지원이 완료됐다고 보고해서는 안 된다.
