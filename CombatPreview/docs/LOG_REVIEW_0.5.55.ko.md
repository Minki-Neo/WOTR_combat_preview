# 0.5.55 공통 주문 매개변수 보강

2026-11-22 최신 세션 8c338f6669a84f41a2c70980394308c3의 초기 검토828건, 런타임0.5.54.0. 이후 게임 진행으로 로그가 추가될 수 있다. 표본의 반복 미리보기 횟수는 고유 주문/시전 횟수와 다르다.

## 확인한 적용과 공백

- 환영 살인마 미리보기4건 중 saveSequence Computed2건/UnavailableLifecycleOrBudget2건. seq397에서 TrackedSaveConsumption/ConditionalTrackedSaveConsumption과 기대 HP감소118.98208678124962가 기록됐다. 이는 0.5.54의 불운 표식 경로가 실제 계산에 연결됐다는 증거다. 실제 즉사 빈도/피해 일치의 검증은 아니다.
- 나머지 미확인2건(seq394/395)은 불운이 아니라 ‘행운과 결의의 축복’의 조건부 내성 보너스다. complete=false, +4, 소모형 재굴림이 함께 기록된다. 보너스 유형별 기존 수치와의 중첩 차이를 아직 계산하지 못한다.
- 독립 매개변수 판독 실패/비교 실패 사유 표본: SpellSpecializationParametrized52, ExpandedArsenal25, SpecialOrUnresolvedParameterSource18, ReplaceAbilityParamsWithContext15. 기존 게임 관측이 있으면 Current여도 독립 비교는 실패할 수 있다. 이 횟수를 전체 UI 실패 횟수로 간주하지 않는다.

## 0.5.55 구현

1. 주문 전문화의 선택 Blueprint와 부모 Blueprint를 읽어 일치하는 주문에 CL+2를 추가한다. 미해당 주문은 계산을 계속한다. 부모 Get을 호출하거나 정의를 로드하지 않는다.
2. 확장된 마법 학파의 실제 등록 학파 목록을 읽는다. 등록된 대상 학파에서는 직접 SpellFocus/SchoolMastery 가산을 건너뛰고 확장 컴포넌트의 전이 경로로 계산한다.
3. 확장 컴포넌트의 m_Focuses/m_SchoolMastery 목록과 진행 특기 목록을 대조한다. 출처 학파별 보정을 합산하고 대상 학파를 제외한 최댓값을 각각 DC/CL에 더한다. 학파별 합계를 전부 더하는 방식이 아니다. 실제 컴포넌트 파생형의 임의 GetBonus 재정의는 미지원으로 남긴다.
4. 신화 중점화는 같은 학파/확장 여부를 적용하며 중복 신화 특기로 반복 배율을 곱하지 않는다. 중요한 엔진 문맥: 확장 컴포넌트가 다른 특기의 Blueprint 컴포넌트.GetBonusDC를 직접 호출하지만 Param은 현재 이벤트 문맥(확장 특기)에서 읽는다. 독립 계산에서도 출처 학파로 무심코 대체하지 않는다.
5. 선택 주문/학파와 실제 확장 등록 목록을 캐시 스탬프에 포함한다. 진행 특기/학파 스냅샷은 하나의 동기 읽기 배치에서만 재사용한다. 다른 프레임으로의 유효기간을 연장하지 않는다.
6. ReplaceAbilityParamsWithContext가 미해당인 주문은 계산을 계속한다. 일치하는 특수 문맥 교체는 ContextParameterOverride로 구분하고 현재는 미지원으로 유지한다.
7. 비중첩 유형 조건부 내성 보너스는 실패 원인을 명시한다. 이를 임의 가산해 확률을 과대 계산하지 않는다.

근거 IL: work/parameter-handlers-055.txt, work/expanded-arsenal-055.txt, work/component-param-055.txt, work/ability-parent-055.txt, work/feature-collection-055.txt. 엔진 이벤트/GetBonus/Get/Ensure를 실행하지 않고 필드·정의·지원된 수학으로 계산한다. HCO 입력은 사용하지 않는다.

## 남은 우선순위

- 행운과 결의의 축복 등 유형별 조건부 내성 보정의 기존 보너스와의 중첩 차이 및 소모 상태 계산.
- 아이템/특수 주문 매개변수, 일치하는 문맥 교체, 도메인/원소 서술자 교체.
- 새0.5.55의 실제 DC/CL/피해·분기·HP바와 관측값 대조. 자동 검사 성공은 실전 일치를 인증하지 않는다.
- 첫 대상의 무거운 계산은 프레임 간 대상 분산과 별개다. 새 버전 CPU/FPS 측정 및 필요 시 대상 내부 분할이 남아 있다. 이번 버전의 성능 개선을 실측했다고 주장하지 않는다.
- 보호막 근사 오차·실제 무기 전체 순서·복합 상태/장판 및 기존 OPEN_ITEMS 목록.
