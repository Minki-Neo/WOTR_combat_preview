# 0.5.60 체력 감소 미리보기 지연 수정

2026-11-23. 사용자 제보: 기대 피해가 보이는데 HP 감소 색상 구간이 비거나 나중에 나타남. 코드에서 서로 다른 원인을 확인해 수정했다. 기존 큐에도 호버 우선순위는 있었지만 이미 처리한 대상을 즉시 재계산하는 경로가 없었다는 점을 구분한다.

## 수정

1. 호버/주문 매개변수 revision 변경 시 이미 처리한 호버 대상도 다시 큐 앞에 넣는다. 다른 대기 대상은 유지하며 제외된 대상을 재유입시키지 않는다. 기존 프레임당2명/3ms soft budget은 유지한다.
2. 호버 대상이 관측된 유효 대상 목록에 있으면 목록 앞에 정렬한 뒤32명 제한을 적용한다. 해당 대상 HP가 먼저 보이도록 한다. 효과 대상 밖의 호버를 강제로 추가하지 않는다.
3. 단계별 expectedHpLoss가null이면 유효한 전체 action-tree HP 결과를 계속 확인한다. 이전 else-if 체인이 null 값에서 멈추던 문제를 보강했다. pit 전용 모형을 일반 분기 값으로 대체하지 않는다.
4. 전체 분기의 expectedDamage가 알려졌지만 HP 분포가 없는 경우 평균 피해/평균 임시 HP 상태의 근사 감소를 즉시 표시한다. 기존 정확한 HP 분포 결과를 우선하며 ≈와 mean-state-hp-display를 기록한다. 피해 분기 하나만 알려지고 즉사 확률이 미확인인 경우, 주변 추가 효과 미계산인 경우는 근사로 채우지 않는다.
5. 무기 기대 피해는 임시 HP가 있다는 이유로 패널 표시를 통째로 보류하지 않는다. max(0, 평균 피해 - 임시 HP)를 현재 HP로 제한한 근사임을 표시한다. 이는 E[min(HP,max(0,D-temp))]의 정확한 분포값이 아니다. 평균이 임시 HP보다 작으면 표시상 감소0일 수 있다. 네이티브 게임 HP바 경로의 기존 임시HP 제약은 유지한다.
6. 양수 감소의 표시 폭이1픽셀 미만이면 사라질 수 있어 색상 구간을 최소1.5픽셀로 표시하되 현재 HP 구간을 넘기지 않는다. 정확한 수치는 캡션에 유지한다. 실제0피해에는 구간을 만들지 않는다.
7. areaScheduling에 hoverChanged/parameterRevisionChanged를 추가하고 healthProjection.basis/approximate로 분포와 평균 표시를 구분한다.

## 검증과 제한

빌드 및 C#25,655개 단언+27-action 회귀, 메타데이터224개, Python19개. 추가16개 검사는 처리 완료 대상 재우선/중복·제외 방지, 빈 단계 결과 뒤 유효 분기 선택, 임시 HP/상한, 미확인 즉사·주변효과 보호, NaN/작은 양수/0색상 폭을 다룬다.

실제 게임 화면에서0.5.60의 지연/색상을 아직 확인하지 않았다. ‘기대 피해’가 기본 주사위 평균만 뜻하고 명중/내성/방어가 아직 미확인인 경우는 전체 HP 예측이 없다. 정확한0감소/미확인/미표시는 서로 구분해야 한다. 기존 복합 축복·전체 주변 전파·특수/장판/치료 문제는 별도다. 게임 파일 교체/재시작을 수행하지 않았다.
